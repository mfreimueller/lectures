* Ich kann erklären, was TypeScript ist und wie es zu JavaScript wird

* Ich kann eine einfache generische Funktion schreiben
* Ich kann vorhandenen JavaScript-Code in TypeScript umschreiben

== Was ist TypeScript?

* Von Microsoft entwickelte Programmiersprache, die auf JavaScript aufbaut
* Erweitert JavaScript um *statische Typisierung* und zusätzliche Features
* Jedes gültige JavaScript ist (fast immer) auch gültiges TypeScript

[.highlight-box]
--
*TypeScript = JavaScript + Typen*
--

* TypeScript wird *nicht direkt ausgeführt*, sondern in JavaScript *transpiliert* (übersetzt)
* Ergebnis: ganz normales JavaScript, das überall läuft – Browser, Node.js, Deno, …

== Von TypeScript zu JavaScript

[source,text]
----
  app.ts  ──── tsc ────►  app.js  ──── node / Browser ────►  Ausführung
 (mit Typen)            (ohne Typen)
----

[source,typescript]
----
// app.ts
function add(a: number, b: number): number {
  return a + b;
}
----

[source,javascript]
----
// app.js (erzeugt von tsc)
function add(a, b) {
  return a + b;
}
----

[.highlight-box]
--
Die Typen existieren nur beim Entwickeln. Zur Laufzeit sind sie verschwunden.
--

== Warum TypeScript?

JavaScript ist flexibel – manchmal zu flexibel. Variablen können zur Laufzeit ihren Typ ändern:

[source,javascript]
----
let price = 19.99;
price = "neunzehn";   // erlaubt in JS – führt aber später zu Fehlern!
----

Mit TypeScript:

[source,typescript]
----
let price: number = 19.99;
price = "neunzehn";   // Fehler beim Kompilieren
----

[.highlight-box]
--
Fehler werden bereits *beim Entwickeln* erkannt – nicht erst im Browser. Dazu kommen Autovervollständigung und Fehlerprüfung in VS Code.
--

== TypeScript für Java-Programmierer:innen

[cols="1,1,1",options="header"]
|===
| | Java | TypeScript
| Typangabe | `int count = 5;` | `let count: number = 5;`
| Zahlen | `int`, `long`, `double`, … | nur `number`
| Text | `String` | `string` (klein!)
| Wahrheitswert | `boolean` | `boolean`
| Rückgabetyp | `int add(int a, int b)` | `add(a: number, b: number): number`
| Typen zur Laufzeit | vorhanden | gelöscht
|===

[.highlight-box.warning]
--
In TypeScript steht der Typ *nach* dem Namen, getrennt durch einen Doppelpunkt.
--

== Projekt anlegen

Neues Verzeichnis anlegen und mit npm initialisieren:

[source,bash]
----
mkdir typescript-project
cd typescript-project
npm init -y
----

TypeScript-Compiler und Linter (ESLint) als Entwicklungsabhängigkeiten installieren:

[source,bash]
----
npm install --save-dev typescript @types/node
npm install --save-dev eslint typescript-eslint globals
----

* `--save-dev`: wird nur beim Entwickeln gebraucht, nicht zur Laufzeit
* `@types/node`: Typdefinitionen für Node.js (z. B. für `console`, `process`)

== tsconfig.json

Konfiguration des TypeScript-Compilers im Stammverzeichnis des Projekts:

[source,json]
----
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "NodeNext",
    "types": ["node"],
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true,
    "sourceMap": true
  }
}
----

* `target`: welche JavaScript-Version erzeugt wird
* `strict`: alle strengen Typprüfungen aktivieren – *immer einschalten*
* `sourceMap`: Debugger zeigt den TypeScript-Code statt des erzeugten JavaScripts

== ESLint & .gitignore

`eslint.config.mjs` im Stammverzeichnis:

[source,javascript]
----
import globals from "globals";
import tseslint from "typescript-eslint";

[source,text]
----

----

== Kompilieren & Ausführen

`src/app.ts`:

[source,typescript]
----
function add(x: number, y: number): number {
  return x + y;
}

const result = add(1, 2);
const result2 = add(1, "x");
// error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
console.log(result);
----

[source,bash]
----
npx tsc && node src/app.js
----

* `npx tsc` übersetzt alle `.ts`-Dateien → `src/app.js`
* `&&`: `node` startet nur, wenn `tsc` *ohne Fehler* durchläuft

== Startskript in package.json

Damit wir den Befehl nicht jedes Mal tippen müssen, legen wir ein Startskript an:

[source,json]
----
{
  // ...
  "scripts": {
    "start": "tsc && node src/app.js"
  }
}
----

[source,bash]
----
npm run start
----

[.highlight-box.warning]
--
Die `package.json` muss gültiges JSON bleiben – auf die Beistriche achten!
--

== Basistypen

[source,typescript]
----
let count: number = 5;
let username: string = "Anna";
let isOnline: boolean = true;
let hobbies: string[] = ["Coding", "Gaming"];
let person: { name: string; age: number } = { name: "Tom", age: 21 };
----

* `number` – alle Zahlen (ganz und Kommazahlen)
* `string`, `boolean` – Text und Wahrheitswerte
* `string[]` – Array von Strings
* `{ name: string; age: number }` – Objekt mit genau diesen Eigenschaften

[.highlight-box]
--
Weitere Typen: `null`, `undefined`, `any`, `void`, `never`, … – `any` schaltet die Typprüfung ab und sollte vermieden werden.
--

== Type Inference

TypeScript erkennt Typen oft *automatisch* aus dem zugewiesenen Wert:

[source,typescript]
----
let x = 10;          // Typ: number
let name = "Anna";   // Typ: string

x = "zehn";          // Fehler: 'string' is not assignable to type 'number'
----

* Bei Variablen mit Startwert ist die Typangabe meist überflüssig
* Bei *Funktionsparametern* gibt es keinen Startwert – dort braucht es die Typangabe

== Funktionen mit Typen

[source,typescript]
----
function add(a: number, b: number): number {
  return a + b;
}

function logMessage(msg: string): void {
  console.log(msg);
}
----

* Parametertypen: `a: number`
* Rückgabetyp nach der Parameterliste: `): number`
* `void`: die Funktion gibt nichts zurück
* Der Rückgabetyp ist optional (Type Inference), aber empfohlen

== Union & Optional Types

*Union Type* – ein Wert darf einen von mehreren Typen haben:

[source,typescript]
----
let id: number | string;
id = 42;
id = "user-42";
----

*Optionaler Parameter* – mit `?` darf das Argument fehlen (dann ist es `undefined`):

[source,typescript]
----
function greet(name?: string) {
  console.log("Hello " + (name ?? "Stranger"));
}

greet();         // Hello Stranger
greet("Anna");   // Hello Anna
----

* `??` (Nullish Coalescing): rechter Wert, wenn der linke `null` oder `undefined` ist

== Type Aliases & Enums

*Type Alias* – einem Typ einen eigenen Namen geben:

[source,typescript]
----
type UserID = number | string;
let userId: UserID = 123;
----

*Enum* – eine feste Menge benannter Konstanten:

[source,typescript]
----
enum Color {
  Red,
  Green,
  Blue,
}

let favoriteColor: Color = Color.Green;
console.log(favoriteColor);   // 1
----

* Ohne Wertangabe werden die Konstanten ab `0` durchnummeriert

== Interfaces

Ein *Interface* beschreibt die Struktur eines Objekts:

[source,typescript]
----
interface Student {
  name: string;
  subject: string;
  grade: number;
  email?: string;   // optionales Feld
}

const student: Student = { name: "Lena", subject: "WMC", grade: 1 };

function printStudent(s: Student) {
  console.log(`${s.name} hat die Note ${s.grade} in ${s.subject}.`);
  if (s.email) console.log(`Email: ${s.email}`);
}
----

[.highlight-box]
--
Anders als in Java braucht ein Objekt kein `implements Student` – die passende Struktur reicht.
--

== Verschachtelte Interfaces & Spread

[source,typescript]
----
interface School {
  name: string;
  students: Student[];   // Array von Student
}

const mySchool: School = {
  name: "HTL Spengergasse",
  students: [
    { name: "Max", subject: "WMC", grade: 2 },
    { name: "Sophie", subject: "WMC", grade: 1, email: "sophie@example.com" },
  ],
};
----

Spread-Operator: Objekt kopieren und dabei Eigenschaften ergänzen – der Typ wird geprüft:

[source,typescript]
----
const updated: Student = { ...student, email: "lena@example.com" };
----

== Klassen

[source,typescript]
----
class Animal {
  constructor(public name: string) {}

  speak(): void {
    console.log(`${this.name} macht ein Geräusch.`);
  }
}

class Dog extends Animal {
  speak(): void {
    console.log(`${this.name} bellt.`);
  }
}

const dog = new Dog("Bello");
dog.speak();   // Bello bellt.
----

* *Parameter Property*: `public name: string` im Konstruktor legt das Feld an *und* weist es zu
* Vererbung mit `extends` – wie in Java

== Funktionstypen

Mit einem Type Alias lässt sich auch die *Signatur einer Funktion* benennen:

[source,typescript]
----
type Greeter = (name: string) => void;
type Calculator = (a: number, b: number) => number;

const greet: Greeter = (name) => console.log(`Hello, ${name}!`);
const add: Calculator = (a, b) => a + b;
const multiply: Calculator = (a, b) => a * b;
----

* Die Parameter von `greet`, `add`, `multiply` brauchen keine Typangabe mehr
* Klare Verträge für Callbacks, Signaturen werden wiederverwendbar

[.highlight-box.warning]
--
Im *Funktionstyp* steht vor dem Rückgabetyp `=>`, in der *Funktionsdeklaration* ein `:`.
--

== Generics

Typsichere Wiederverwendung: Der Typ wird zum *Parameter* `T`:

[source,typescript]
----
function getFirst<T>(arr: T[]): T {
  return arr[0];
}

const first = getFirst([1, 2, 3]);         // T = number → 1
const name = getFirst(["Anna", "Bob"]);    // T = string → "Anna"
----

* `<T>` nach dem Funktionsnamen führt den Typparameter ein
* TypeScript leitet `T` aus dem Argument ab
* Wie Generics in Java (`List<T>`) – nur ohne `List`: Arrays schreibt man `T[]`

[.highlight-box]
--
Mit `any` statt `T` würde es auch kompilieren – aber `first` wäre dann `any` und jede Typprüfung weg.
--

== Interface vs. Type Alias

[source,typescript]
----
interface Point {
  x: number;
  y: number;
}

type Coordinate = {
  x: number;
  y: number;
};
----

* Beide beschreiben die Struktur eines Objekts
* Interfaces können erweitert werden (`interface Point3D extends Point`)
* Type Aliases sind flexibler: Union Types, Funktionstypen, …

[.highlight-box]
--
*Faustregel:* Interfaces für Objektstrukturen, Type Aliases für alles andere.
--

== Zusammenfassung

* TypeScript = JavaScript + Typen, wird mit `tsc` zu JavaScript übersetzt
* Setup: `npm init`, `typescript` + ESLint installieren, `tsconfig.json` mit `strict`
* Typ nach dem Namen: `let x: number`, `function f(a: string): void`
* `|` für Union Types, `?` für optionale Werte, `type` für eigene Typnamen
* `interface` beschreibt Objekte, Klassen kennen Parameter Properties
* Generics `<T>` machen Funktionen typsicher wiederverwendbar
