== Warum Repositories testen?

* Überprüfen ob JPA Mappings tatsächlich funktionieren
* Regressionen bei Schemaänderungen erkennen
* Benutzerdefinierte Abfragen gegen echtes SQL testen
* In CI ausführen — keine echte Datenbank nötig

== @DataJpaTest

* Ein "Slice Test" — lädt nur JPA-beans
* Konfiguriert H2 In-Memory Datenbank automatisch
* Nach jedem Test zurückgesetzt (transaktional)
* Injected TestEntityManager für zusätzliche Kontrolle

== Test-Setup

[source,java]
----
@DataJpaTest
class BookRepositoryTest {

    @Autowired
    private BookRepository bookRepo;

    @Autowired
    private TestEntityManager entityManager;

    @BeforeEach
    void setUp() {
        book1 = new Book("123-4", "Java Basics", 2020);
        book2 = new Book("567-8", "Spring Boot", 2022);
        bookRepo.saveAll(List.of(book1, book2));
    }
}
----

== Der Lifecycle-Test

[source,java]
----
@Test
void verify_book_can_be_saved_and_read() {
    Book book = new Book("9783161484100", "Dune", new BigDecimal("12.90"),
                         LocalDate.of(1965, 8, 1));

    bookRepo.save(book);
    entityManager.flush();     // INSERT wirklich ausführen
    entityManager.clear();     // First-Level-Cache leeren

    Book reread = bookRepo.findById(book.getId()).orElseThrow();
    assertThat(reread).isNotSameAs(book);                 // wirklich neu gelesen
    assertThat(reread.getTitle()).isEqualTo("Dune");
    assertThat(reread.getPrice()).isEqualByComparingTo("12.90");
}
----

Ohne `clear()` kommt dasselbe Objekt aus dem Cache zurück — Mapping-Fehler (fehlender No-Args-Konstruktor, falscher Converter) bleiben unentdeckt.

== `save` vs. `saveAndFlush`

[source,java]
----
@Test
void verify_isbn_is_unique() {
    bookRepo.saveAndFlush(book("9783161484100", "Erstes Buch"));

    assertThatThrownBy(() -> bookRepo.saveAndFlush(book("9783161484100", "Zweites Buch")))
        .isInstanceOf(DataIntegrityViolationException.class);
}

@Test
void verify_title_is_required() {
    assertThatThrownBy(() -> bookRepo.saveAndFlush(book("9783161484100", null)))
        .isInstanceOf(ConstraintViolationException.class);   // jakarta.validation
}
----

* Mit `@GeneratedValue` (Sequence) wird erst beim *Flush* eingefügt
* Ein Test mit nur `save` sieht die Constraint-Verletzung *nie*

== TestEntityManager

[cols="1,2",options="header"]
|===
|Methode |Macht
|`persist(entity)` |speichert (wie `save`), Cascade gilt
|`persistAndFlush(entity)` |speichert und schreibt sofort
|`persistFlushFind(entity)` |speichert, schreibt, leert Cache, liest neu
|`find(Type.class, id)` |liest über die Id
|`flush()` / `clear()` |schreiben / Cache leeren
|===

[source,java]
----
Author author = entityManager.persistFlushFind(new Author("Paul Celan"));
assertThat(author.getId()).isNotNull();
----

== Was ein vollständiger Testsatz enthält

. *Entity*: speichern und lesen (Lifecycle-Test)
. *Constraints*: ungültige Daten werden abgelehnt
. *Value Object*: Spalten und Validierung über das besitzende Entity
. *Rich Type / Enum*: Converter einzeln testen (auch `null`), gespeicherten Wert prüfen
. *Beziehung*: Graph speichern, neu lesen, beide Richtungen prüfen
. *Abfrage*: Testdaten, die Treffer auch *ausschließen*

[.highlight-box]
--
Ungetestete Klassen werden bei der Beurteilung nicht berücksichtigt.
